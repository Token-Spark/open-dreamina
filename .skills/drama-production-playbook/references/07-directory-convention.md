# 07 标准目录规范与审阅中心对接

## 目录总图

见 `drama/README.md` 的「标准项目目录」一节（规范唯一出处，此处讲设计理由与对接）。

## 三条目录铁律

1. **`_` 前缀 = 机器可见、审阅不可见**：`_SPEC_*.md`、`_superseded_*`、`_model_compare/`
   等内部产物放 `_` 前缀目录，镜头审片扫描自动跳过——当前交付永远干净。
2. **生成结果与素材物理隔离**：`video_renders/` 只放镜头视频，素材库只放素材；
   重新生成覆盖前者、更新素材不动后者（用户调研经验 5 的落地）。
3. **数据在 tools/，产物在项目根**：manifest / spec / registry / maps 是"数据"，
   素材库 / 成片 / 抽帧是"产物"；工具链写数据、生成器写产物，互不越界。

## 审阅中心零配置对接

把项目根放进 `data/review_sources/`（默认挂载）即完成全部对接：

| 审阅模式 | 扫描位置 | 自动行为 |
|---|---|---|
| 素材审阅 `/review` | `素材库/` 全部子目录 | 数字前缀分类呈现层级；缩略图生成在 `data/review_thumbs/`，不动素材 |
| 镜头审片 `/review?mode=shot` | `分镜脚本/EPxx/video_renders/` | 按 `EPxx/Sxx` 解析集镜号；`shots.md` 关联为「应有」底稿；`_` 目录跳过；同镜号多版本合并对比 |
| 审片归档 | （自动）`data/review_archive/` | 打分/意见/精修/删除动作无感沉淀为 markdown；删废弃版本前自动抢救副本 |

挂载要点（AGENTS.md 同款约束）：

- 素材审阅挂载只读（`:ro`），审阅不写素材目录
- 镜头审片另有可写挂载（`SHOT_REVIEW_SOURCES_HOST_PATH`），用于物理删除废弃视频
- 改挂载配置需 `docker compose up -d --build` 重建
