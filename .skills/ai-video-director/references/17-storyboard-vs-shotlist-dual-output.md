# 分镜图 vs 分镜头脚本：双产物、12 字段与管线保护

> 专业知识层 `17`，服务 STEP 3 / STEP 10，是导演设计稿与机器可解析脚本之间的**唯一接口**。
> 本文件定义的约束优先于任何新增字段需求：**`shots.md` 与 `drama lint` 不可改动**。

## 1. 两种产物，不要混为一谈

| | Storyboard 分镜图 | Shot List / 分镜头脚本 |
|---|---|---|
| 性质 | **视觉化参考**（画格、机位图、调度示意） | **镜头执行方案**（可据此生成、可验收的文字规格） |
| 回答 | 画面看起来是什么样 | 每一镜拍什么、怎么拍、多长、怎么接、怎么生成 |
| 消费者 | 导演、美术、关键帧生成 | 制片执行、生成管线、审片 |
| 本技能落点 | `16` 的画格 + `13` 的机位图 | `02` 的 Shot 字段 + `10` 的生成卡 + `shots.md` |

> 学习任务里的核心判断：**不要把分镜图等同于分镜头脚本**。
> 对 AI 制作，两者都要有，且以 Shot ID 一一对应。

## 2. 交付清单（缺一不可）

```text
1. Storyboard（画格或文字故事板，见 16 §4）
2. 机位图 / 轴线标注（见 13 §4）
3. 分镜头脚本（12 字段完整，见 §3）+ 切点表（见 15 §5）+ 视点表（见 14 §5）
4. 逐镜头生成卡（Image/Video Prompt，见 10 §2）
5. shots.md（仅当进 Open Dreamina 管线时，见 drama-shotlist-spec.md）
6. 导演设计 sidecar：{项目根}/导演设计/EPxx/shot-design.md
```

## 3. 分镜头脚本 12 字段（定义与取值）

| # | 字段 | 定义 / 取值要求 |
|---:|---|---|
| 1 | Shot ID | `EPxx-SNN`，全场唯一，与 5 类产物一一对应 |
| 2 | 画面内容 | 一句话：谁 + 在哪 + 做什么；不写心理、不写解释 |
| 3 | 景别 | 用 `03` 七级体系；进管线时投影到 drama 枚举 |
| 4 | 机位 | 角度 + 位置 + **轴线侧**（见 `13`） |
| 5 | 镜头运动 | 摄影机的运动方式、起止、速度；静止写 `static` |
| 6 | 人物运动 | 与镜头运动**分开写**：起姿势 → 路径 → 止姿势 |
| 7 | 构图 | 主体位置、留白、前中后景、平衡 / 失衡 |
| 8 | 灯光 | 动机光 + 光比 + 色温；全局常量按 ID 引用 |
| 9 | 时长 | 秒；与总时长合计校验（drama 为 90s） |
| 10 | 声音 | 对白 / 环境 / 动效 / 音乐 Cue / 静默 |
| 11 | 转场 | 与下一镜的剪辑方式 + **切点依据**（见 `15` §2） |
| 12 | AI 生成指令 | 固定角色参考图 ID、场景参考图 ID、**关系关键帧 ID（多人 / 共现组合必填，见 `19`）**、**室内朝向锚点 ID（室内多角度必填，见 `20`）**、本镜描述、负面词、参数 |

字段 11 必须回答「为什么在此刻切」，字段 12 必须引用已锁定的资产 ID
（`05-continuity-and-lock.md`），禁止每镜重新描述角色 / 场景。

## 4. 四向字段映射表（关键）

| 12 字段 | `02` Shot 19 字段 | drama 15 列总览表 / 15 行模板 | `10` 生成卡 |
|---|---|---|---|
| Shot ID | Shot ID | `## EPxx-SNN` / 镜号列 | SHOT ID |
| 画面内容 | Subject + Action + Expression + Environment | 人物 / 场景描述 / 细节 / 秒级动作拆解（组合） | PURPOSE + ACTION |
| 景别 | Shot Size | **景别列**（模板内无独立行） | SHOT |
| 机位 | Camera Angle + Camera Position | **机位列**（模板内无独立行） | CAMERA |
| 镜头运动 | Camera Movement | **运镜列** + 秒级动作拆解的 `运镜：` 子行 | CAMERA |
| 人物运动 | Action（当前与镜头运动混写） | 秒级动作拆解 | ACTION |
| 构图 | Composition | 构图行 / 构图列 | COMPOSITION |
| 灯光 | Lighting | 光感 / 色调行 / 灯光·色调列 | LIGHTING |
| 时长 | Duration | **时长列**（模板内靠 `0-4s` 隐含） | DURATION |
| 声音 | Sound + Dialogue | 台词同步 / 音效设计 / 基础环境音 / 动作触发音 / 特效音 / 声音列 | SFX / MUSIC / VIDEO PROMPT |
| 转场 | Transition | **衔接列**（须按剪辑转场语义填写） | EDIT |
| AI 生成指令 | **缺失** | **不承载**（见 §5） | IMAGE PROMPT / VIDEO PROMPT / NEGATIVE |

**结论**：最大缺口不是字段数量，而是**两套语言之间原本没有映射表**——
`02` 的 19 字段与 drama 的 15 行 / 15 列靠人工重述衔接，导致 `10` §1
Shot Table 示例出现列错位。任何新增规范都必须经本表投影。

## 5. 管线保护条款（不可协商）

`shots.md` 是 `drama lint` / `drama parse` 的**唯一机器入口**。以下全部**禁止改动**：

1. 逐镜块标题严格 `## EPxx-SNN`，**不得加后缀**（如 `· 机位图`），否则 lint 判定缺块。
2. 15 列总览表的**列数与列序固定**（解析器按下标取值），不插列、不改序。
3. 单镜 15 行模板的**必填行顺序固定**，不新增行、不删行。
4. 镜头数 18±1、单镜 2–8s、总时长 90s、每集 ≥1 POV、台词逐字引用、禁「同上」、
   人物资产只绑 `*_turnaround` —— 全部保留。
5. 摄影枚举以**代码 `drama/parser/shots_parser.py` 的 `CAMERA_PHRASE` 为准**；
   `drama-shotlist-spec.md` 列的是子集，新增写法先核对代码，否则编译时被丢弃。
6. **AI 生成指令不写入 `shots.md`**：遵守既有契约，由 `production-orchestrator`
   从 parse 结果生成 spec；sidecar 只写「生成指令摘要」。

### 安全扩展通道

| 优先级 | 通道 | 说明 |
|---|---|---|
| **A（推荐）** | **sidecar**：`{项目根}/导演设计/EPxx/shot-design.md` | lint 只读 `分镜脚本/EPxx/shots.md` 单一路径，新增文件**完全不进扫描，零风险** |
| B | HTML 注释 `<!-- … -->` | parser 的 `strip_html_comments` 会在校验前剥离，人可读、机器不报错；仅供人审，不被 compiler 消费 |
| 禁止 | 改 15 行模板 / 改 lint 代码 / 在总览表插列 | 属于改动管线，超出技能规范范围 |

## 6. sidecar 模板

```markdown
# EPxx 导演设计稿（与 shots.md 以 Shot ID 一一对应）

## EP05-S08
- 12 字段：（按 §3 全填）
- 四问校验：景别为何 / 角度为何 / 运镜为何 / 剪辑点为何（见 15 §2 主理由）
- 视点与信息差：（见 14 §2 矩阵）
- 轴线侧 / 机位号：（引用本集机位图）
- 生成指令摘要：资产 ID + 关键描述（完整 Prompt 见 10 §2 生成卡）
- 关系关键帧：`rel_..._v1` / asset_id / 批准状态 / 本镜沿用站位 / 关系变更点（见 19 §8）
- 室内朝向锚点：`loc_..._viewA_v1` / asset_id / 本镜机位朝向 / 布局总览引用（见 20 §6）
```

## 7. 校验（STEP 10 / 最终验收）

- 每个 Shot 必须通过**四问**：为什么是这个景别 / 这个角度 / 这个运镜 / 这个剪辑点。
- 12 字段齐全，且经 §4 映射表投影到 drama 总览表；扩展信息只在 sidecar。
- Storyboard 与 Shot List 以 `EPxx-SNN` 一一对应，缺格或缺镜都要列出。
- `shots.md` 通过 `drama lint`（errors = 0）才算完成；sidecar 不参与 lint，但必须随交付。

## 8. 边界

- 不重复 `10` §2 的逐镜头生成卡模板与 `drama-shotlist-spec.md` 的模板原文。
- 不修改任何 `drama/` 下的代码；本文件只定义技能侧的使用契约。
