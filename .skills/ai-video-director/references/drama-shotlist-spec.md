# Drama Shotlist Spec — 竖屏短剧分镜模板规范

> 本文件是 ai-video-director 技能的短剧专章：当分镜产出要进入 Open Dreamina
> 短剧制作管线（drama-production-playbook / `opendreamina drama` 工具链）时，
> 分镜必须按本模板书写——它是机器可解析的（`drama lint` 校验、`drama parse` 消费）。

## 输出位置与文件结构

每集一个文件：`{项目根}/分镜脚本/EPxx/shots.md`：

1. 一级标题：`# EPxx · 集名`（含时长 / 镜头数 / 画幅 / 场景 / 核心情绪）
2. 生产说明：全局风格常量（从 manifest style 引用，禁止自创）+ 音频约定
3. 总览表（15 列，时长合计 = 90s）
4. 逐镜头块：每镜一个 `## EPxx-SNN`
5. 质检清单

## 总览表（15 列，顺序固定）

```markdown
| 镜号 | 时长 | 景别 | 机位 | 运镜 | 构图 | 动作 | 表情 | 灯光 | 色调 | 环境 | 声音 | 台词 | 特效 | 衔接 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| EP05-S01 | 4 | wide | high-angle | slow-tilt-down | 对称失衡 | 俯瞰… | 木然 | 单支烛光暖调 | 暖黄+阴影 | 锻造坊 | 远处打铁声 | — | — | 本集起幅：空镜俯瞰锻造坊，无人物入画 |
```

景别/机位/运镜必须用规范枚举（未收录写法编译时被丢弃）：
`wide/medium/close_up/extreme_close_up/full`、`eye-level/low-angle/high-angle/overhead/handheld`、
`static/slow-push/slow-pull/slow-pan/slow-tilt-up/slow-tilt-down/handheld-sway/follow/quick-pan`。

## 「衔接」列怎么写（入场态，不是剪辑注释）

这一列写的是**本镜第 0 帧的入场态**，不是"淡入淡出""交叉溶解"这类转场术语：
转场类型属于剪辑方案（`08`/`15`），入场态属于生成约束。三组都要有值——
**人物位置关系 / 环境 / 动作与表情**，压成一句话。

格式：`级别标记 接 S{上一镜号}：谁在画面哪一侧、朝向、动作在第几拍、表情余势、光从哪来`。

| 写法 | 含义 |
|---|---|
| `[A] 接 S03：林在画面右，侧身背对镜头，右手持刀已过肩，下颌绷紧，烛光仍在左侧` | A 硬接，三组逐条对齐 |
| `[B] 接 S05：林已坐回桌边（时间跳过约 10 分钟），眉头松开，暖光转冷` | B 软接，位置与环境对齐、表情有过渡 |
| `[C] 转场：次日清晨，门外走廊` | C 断接，不强求动作连续 |
| `本集起幅：空镜俯瞰锻造坊，炉火在左后，无人物入画` | 本集首镜，不做接续 |

规则：

- **每镜必填**，本集首镜写「本集起幅」。空着 = 没想过怎么接（`22` §8 门禁第 1 条）。
- 三组不能省：只写"接上镜"不算，得写清人在哪、屋里与光什么状态、动作到哪一拍、脸是什么表情。
- 列内**禁止 `|` 与换行**，否则表结构错位、解析取不到该行。
- 只写状态，不写上一镜的动作（"他刚放下杯子"会诱发重演，写"杯子已在桌上"）。
- 表情写**余势**不写结果（"下颌绷紧"而非"他平静下来"）——表情无过渡地跳变，观众立刻出戏。
- 不写服饰 / 陈设细节——那属 `21` 的锚点，重述会漂移。

> **代码事实**：该列**不参与 `drama compile`**（`parse_overview()` 只取第 6–13 列）。
> 所以入场态还有第二个落点——一句英文接续句写进人物行英文锚点或编译后的 prompt 首部，
> 写法与优先级见 `22-shot-continuity-in-generation.md` §5.1/§10。只写在本列 = 模型看不到。


## 单镜 15 行模板（顺序固定，缺行 = lint error）

```markdown
## EP05-S08

**镜头功能：** 对话，固定镜头（对话/反应/建立/POV/反转/插入）
**资产绑定：** 角色：char_venus_s1_turnaround ｜ 场景：scene_forge_interior ｜ 道具：prop_metal_rose ｜ 音色：voice_venus
**人物：** Venus（英文外观锚点逐字写全，绝不写「同上」；不入画角色标注「不入画」）
**场景描述：** 场景锚点："Interior of the same blacksmith forge, ...（英文逐字）"
**秒级动作拆解：**
- 0-4s：动作描述；运镜：缓慢推近
**台词同步：**
- Venus（语速 2.5 字/秒，台词："英文台词逐字引用分集剧本"）
**光感：** 午后金色侧逆光
**色调：** 暖金+暗绿
**构图：** 三分法，人物占画面 75%
**细节：** 手部特写道具
**音效设计：** 无背景音乐
**基础环境音：** 炉火噼啪
**动作触发音：** 金属轻碰
**特效音：** —
```

## 硬性规则（drama lint 校验）

- 镜头数 18（±1）、总览表时长合计 = 目标时长
- 单镜时长**三层口径**（代码事实：`drama/lint/shots_lint.py:43` 的 `shot_min=2 / shot_max=8 / soft_max=6`）：
  硬区间 **2–8s**（超出 = lint error）｜建议上限 / 创作建议 **6s**（超出仅 warning）
  ——创作层的「≤6s」与 lint 的「2-8s」不是两套规则
- 必填行齐全；禁止相对引用；台词写在引号内（解析依赖）
- 每集至少 1 个 POV 主观镜头
- 人物资产只绑 `*_turnaround` 三视图（解析器自动过滤半身照/种子图引用）
- 台词逐字引用分集剧本——导演无权改写台词
- 「衔接」列入场态每镜必填（本集首镜写「本集起幅」），三组（位置关系 / 环境 / 动作与表情）缺一不可，
  A 级硬接尤甚；这是**人工 / agent 检查项，lint 不校验**（改 lint 属代码任务，另开），判定与门禁见 `22` §3/§8

## AIGC 生成意识（设计即规避）

- 单镜创作建议 ≤6s（= lint 的 `soft_max`）；多人互动 / 长台词例外可放宽至 8s 硬上限，但要接受更高重生成率
- 一个镜头一个主要视觉任务；复杂动作拆镜
- **连拍组不改分镜结构，只改生成粒度**：同场同时段的连续镜头（A 硬接 / 正反打 / 跟拍 / 同场换机位 / 空镜序列）
  在生成侧合并为一次任务（Seedance 2.5 ≤30s，组内 2–4 镜、推荐 12–20s），
  `shots.md` 仍是逐镜一行一块、时长与「衔接」列照旧填写（组内第二镜起的入场态）
- 多人同镜 / 人物-场景反复共现 / 共享站位的正反打，以及室内跨 ≥2 机位/朝向，须先批准 `rel_*` / `loc_*` 锚点（拆正反打不免除、合组也不免除）；触发条件、门禁、登记与 `shots.md` 兼容见 `19-relationship-keyframe.md` §2/§6/§8 与 `20-indoor-layout-anchor.md` §2/§7
- 心理/说话画面：人物占画面 75% 以上
- 禁止夸张特效与复杂运镜（详见 drama-production-playbook references/03）
- **接续靠提示词，不靠尾帧**：默认 `--frame-mode reference`，模型看不到上一镜画面，
  衔接由「英文入场句 + 同版本参考复用」保证；尾帧只作人工比对基准，不作首帧（`22` §5.3）
- **能合就别拆**：拆开之前先按 `23` 判断能不能编成连拍组——组内切点由模型自己接，
  比任何接续句都准；必须拆的只有跨场跨时、多人物理接触、精确咬口型特写、复杂运镜/特效合成点、需精确起幅的镜

## 机器检查与下游

```bash
opendreamina drama lint EPxx   # errors=0 才能交给制片执行
opendreamina drama parse EPxx  # 结构化预览（检查锚点/台词解析结果）
```

`drama compile` 的产物**不含接续句**（编译器只吃单镜字段）。生成前须按 `22` §5.1 把入场句
前插到 `tools/episode_specs/EPxx.json` 的 `shots[].prompt` 首部，或提前写进人物行英文锚点让它自然编译进去；
前插属于允许的生成侧增补，须回写 sidecar 接续链表。

**连拍组表也写 sidecar**（`导演设计/EPxx/shot-design.md`，格式见 `23` §6）：`TG 编号 / 包含镜号 / 各镜时长 / 组总长 / 切点 / 母版`。
`shots.md` 与 `episode_spec` 结构不变；编组只影响执行层的合并调用与产物裁切，
**不新增行、不新增列、不改 lint 硬规则**。

分镜通过 lint 后进入 production-orchestrator（spec 生成、编组与批量生成）。
