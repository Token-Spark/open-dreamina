# 室内布局与全景锚点：多角度场景的空间一致性

> 专业知识层 `20`，服务 STEP 5（场景资产）、STEP 9（门禁）与 STEP 10（交付）。
> 与 `19-relationship-keyframe.md` 分工：**`20` 锁「房间长什么样、哪面墙在哪」，
> `19` 锁「人站在哪」**。室内多人场景两者叠加，顺序见 §7。

## 1. 为什么一张 primary 不够

`drama-production-playbook/references/04-consistency-strategy.md` 第 3 层规定
「每场景仅一张 primary 外观图」。这对**单机位**场景成立，但一张图只覆盖一个朝向：

| 现象 | 根因 |
|---|---|
| 正反打时 A 面墙和 B 面墙对不上 | 反打方向没有参考图，模型自己编一面墙 |
| 门窗 / 家具在相邻镜头里换位置 | 每次生成重新构图，没有整体结构约束 |
| 人物走动后背景空间不连贯 | 没有房间平面，无法推导「走过这扇门会到哪」 |
| 光线方向反转 | 没锁定窗在哪一侧 |
| 跨集同一室内越拍越不像 | 只靠文字复述房间，文字与图冲突时模型自行发挥 |

> 结论：室内多角度场景必须先让 AI 生成**房间整体布局 / 全景**，
> 把它作为空间事实源，再按机位朝向派生各镜参考。
> 文字写「同一间书房」不等于锚定。

## 2. 触发条件（命中任一即必须建布局/全景锚点）

1. 同一室内场景出现 **≥2 个机位或朝向**（正反打、过肩、俯仰、越轴都算）。
2. 场景内有门 / 窗 / 楼梯 / 多个功能分区，且跨镜头可见。
3. 人物在场景内移动，或镜头跟随穿过空间。
4. 同一室内跨集反复出现。
5. 反打镜头背景应显示特定墙面 / 道具。

外景、单固定机位、纯特写（背景虚化不可辨）可豁免。

## 3. 两级产物（不要混）

| 产物 | 视角 | 用途 | 是否作生成参考 |
|---|---|---|---|
| **布局总览图** | 俯视 / 30° 轴测，显示完整平面 | 设计基准：房间形状、门窗位置、家具、分区、机位编号与轴线 | **否**（拿它当参考会生成鸟瞰镜头） |
| **全景锚点组** | 各朝向的 eye-level 视角（A/B/C…），或宽幅多视角拼接 | 按机位朝向引用的生成参考 | **是** |

布局总览用于**对齐设计与生成**：`13` 的机位图 C1/C2、轴线、Screen Direction
必须与它用同一套朝向编号。全景锚点才进 `reference_asset_ids`。

## 4. 如何引导 AI 生成（提示词骨架）

顺序固定：**先总览 → 再按朝向派生**，全部固定 seed 并逐字拼接风格四常量
（`drama compile --with-style` 自动追加，禁止手写改写）。

布局总览（文生图）：

```text
top-down axonometric view of a single continuous interior, {房间类型/用途},
showing the complete floor plan: {门的位置}, {窗的位置与朝向}, {主要家具与固定摆位},
{功能分区}, {层高与结构特征}, consistent architectural style,
no people, no cropped walls, no text, even neutral lighting

尾部逐字拼接 {AESTHETIC} + {MEDIUM}；负面词含 {NEGATIVE} +
people, text, floating furniture, duplicated windows, warped perspective
```

全景 / 朝向锚点（图生图，以总览 + primary 为参考）：

```text
eye-level view from {基准点}, facing {A 面墙 / 门 / 窗},
same room, same furniture placement, same window and door positions
as the layout reference image, {光向与时间}, no people

以总览图 + 场景 primary 作 img2img 参考；同 seed、同风格常量；
提示词只做「same as the layout reference image」锚定，减少环境文字描写
```

要点：

- **先写死不变项**（门窗、家具摆位、光向），再写可变项（时间 / 天气 / 节庆态）。
- 每个朝向单独出一张，不要指望一张图覆盖 360°。
- 变体（夜晚态、节庆态）从对应朝向锚点重绘派生，不是重新文生图。
- 若上游支持 360 全景或多图参考，可用一张宽幅多视角拼接图替代锚点组；
  否则用 2–4 张互补视角，按机位朝向选。

## 5. 机位 → 锚点映射

| 机位（`13` 号机位图） | 朝向 | 引用锚点 |
|---|---|---|
| C1 外反打 A | 面向 A 面墙 | `loc_{场景}_viewA_v1` |
| C2 外反打 B | 面向 B 面墙 | `loc_{场景}_viewB_v1` |
| C3 骑轴 / 建立 | 房间对角 | `loc_{场景}_viewWide_v1` |

每个 Shot 在 sidecar 记录「机位号 / 朝向 / 锚点 ID」；反打两侧必须**互补**
（A 镜背景是 A 墙，B 镜背景是 B 墙），而不是复用同一张图。

## 6. 命名、登记与版本

```text
loc_{场景}_layout_v1           布局总览（设计基准，可不登记 asset_id）
loc_{场景}_view{A|B|C|Wide}_v1  朝向锚点（必须登记 asset_id）
```

- 登记、白名单代码事实与生成消费统一见 `19` §8（本文件不重复展开）。
- 布局总览图不进生成参考，可不登记 `asset_id`；朝向锚点必须登记。
- 同一房间 + 同一空间状态复用同一版本；改结构（挪家具 / 昼夜 / 季节）
  才新建 `v2`，旧版保留。
- primary 仍是风格 / 材质事实源；朝向锚点是它的**合法派生**，两者不冲突。

## 7. 生成门禁与顺序

```text
室内布局总览 / 全景锚点组（20）
  → 关系关键帧（19，多人 / 共现时）
  → 单镜关键帧
  → 视频
```

室内场景**布局未定，关系帧不许开工**——关系帧必须画在同一个房间的同一套结构上。
触发条件命中但布局 / 全景锚点缺失或未批准 → 任务标记 `BLOCKED`，不得生成；
按机位朝向引用错误锚点同样 `BLOCKED`。

生成时的多参考组合：

```text
该机位朝向的全景锚点（房间结构）
+ 关系关键帧（人物站位，若命中 19）
+ 各角色 *_turnaround（身份）
+ 全局风格四常量（逐字拼接）
```

`frame_mode: reference` 优先（Seedance 实测），`first_last` 慎用。
提示词只写「延续参考图的房间结构、门窗位置与光向」+ 本镜动作，不重述房间。

## 8. QC 验收

- **关键帧 QC**：门窗 / 家具 / 墙面位置、光向是否与该朝向锚点一致。
- **视频 QC**：运动中背景结构是否变形；正反打两侧是否互补；相邻镜头的门窗是否跳位。
- **审片**：对照布局总览与机位图；结构错位 → 降档，精修提示词写明
  「回到 `loc_..._viewB_v1` 的房间结构」。
