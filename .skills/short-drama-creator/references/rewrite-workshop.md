# 分层改稿工作坊（UCLA Rewrite Workshop）

> 对应 SKILL.md 索引中的 `references/rewrite-workshop.md`。
> STEP 9–12 加载。现有 STEP 12 的「<80 重写 / <70 重新设计」是**单集体检**；
> 本文件补上 UCLA 式的**全稿按稿次演进**：每一稿只解决一层问题。

## 1. 四稿分层与各稿 Gate

| 稿次 | 唯一目标 | 允许改什么 | 禁止提前做 | 退出条件（Gate） |
|---|---|---|---|---|
| **D1 讲得出来** | 把故事从头到尾讲通 | 事件顺序、因果链、结局存在 | 改对白、抠格式、加钩子、打磨节奏 | 任何人读完能复述「谁想要什么、最后怎样了」 |
| **D2 故事成立** | 结构与因果经得起追问 | 激励事件、进展纠葛、危机、高潮、价值转折、伏笔回应 | 润色对白、调整场景措辞 | 序列五节点齐全；每场有价值变化；无「靠巧合推进」 |
| **D3 人物真实** | 人物不是被情节推着走的工具 | 弧光 Lie/Truth、动机连续、两难选择、潜台词、人物网 | 只改台词不改行为 | 人物真相只在不可逆选择中揭示；无工具人；删掉台词仍能看出他是谁 |
| **D4 打磨** | 交付级成稿 | 对白、节奏、标准剧本格式、视觉重点、逐字校 | 再动结构（结构问题回 D2） | 通过 `quality-control.md` 评分与五项门槛 |

> 第一稿解决「能不能讲出来」，第二稿解决「是否成立」，
> 第三稿解决「人物是否真实、情节是否有吸引力」，后续才逐步接近成熟作品。
> **禁止在 D1 阶段打磨对白**——那是用最容易的部分逃避最难的部分。

## 2. 双轨重写（与 STEP 12 合并执行）

```text
轨道 A：单集评分阈值（既有）
  Score < 80 → 重写；< 70 → 重新设计 Hook / Conflict / Episode Structure
轨道 B：全稿稿次演进（本文件）
  D1 → D2 → D3 → D4，每稿只通过对应 Gate 才进下一稿
```

冲突处理：评分 <70 时**不再一律返回 STEP 1**，而是按诊断落到**对应稿次目标**：

| 诊断结论 | 回到的目标 | 不做什么 |
|---|---|---|
| 因果断裂 / 激励事件缺失 | D2 | 不重写已成立的人物弧光 |
| 人物动机不连续 / 工具人 | D3 | 不推倒已成立的结构 |
| 钩子弱 / 台词生硬 / 格式错 | D4 | 不动结构与人设 |
| Premise / 主题不成立 | D1 之前（`premise-theme.md`） | 不靠打磨补救 |

`workflow.md` STEP 12 的「自动重写 → 返回 STEP 1」据此改为
「→ 返回对应稿次目标」，避免每次推倒重来造成的能力与成本浪费。

## 3. 诊断 → 处方（复用既有 20 问，按稿次归层）

`quality-control.md` §4 的 Agent 自检 20 问不新增、不改写，只**按稿次重新归层**：

| 稿次 | 优先调用的自检问 | 对应处方文件 |
|---|---|---|
| D1 | 故事能否复述、结局是否闭合 | `workflow.md` STEP 6 |
| D2 | 因果、转折、伏笔、Escalation | `story-anatomy.md` §1–3、`episode-structure.md` §6 |
| D3 | 选择是否不可逆、是否工具人、人物是否变化 | `character-arc.md` §2–3、`episode-structure.md` §4 |
| D4 | 潜台词、信息密度、可拍摄性、格式 | `narrative-craft.md` §6–8、`story-anatomy.md` §5 |

规则：**一稿只答本层的问**。D2 阶段不因「台词不够漂亮」返工。

## 4. 工作坊机制

### Table Read / 冷读

1. 出声读完整稿（Agent 可逐场复述），记录**卡住 / 走神 / 需要回看**的位置。
2. 只记录现象与时间点，不在朗读时改稿。
3. 冷读反馈协议（同伴 / 用户 / 另一个 Agent）：
   - 只说「我在哪里困惑、我以为会发生什么」；
   - **禁止直接给方案**（「你应该让……」）；方案由作者诊断后自己开。
4. 反馈 → 诊断 → 处方三栏记录，处方必须指向具体稿次与具体场号。

### 改稿日志

```text
版本：D2.1（稿次.序号）
本稿目标：（一句话，来自 §1 的 Gate）
诊断：（来自冷读 / 自检的问题，带场号）
处方：（改什么、不改什么）
变更清单：场号 → 改动摘要
未解决问题：（明示带入下一稿，不隐藏）
Gate 结论：通过 / 未通过（原因）
```

版本纪律：稿次编号只增不减；**废弃稿不删除**，存 `{项目根}/_revisions/`
（与 `drama-production-playbook` 的 `_superseded_*` 沉淀纪律一致）。

## 5. 与评分的关系

- `quality-control.md` 的 100 分制是**每集、每稿都可跑**的体检，不替代稿次 Gate。
- D1 / D2 / D3 稿**不要求 ≥80 分**；用分数逼早期稿打磨会诱发「提前润色」。
- 只有 **D4** 稿才执行「<80 重写 / <70 重新设计」的阈值判定。
- 最终交付物必须附改稿日志（见 SKILL.md Final Output）。

## 6. 边界

- 不重复 `quality-control.md` 的评分表、五项门槛与 20 问原文。
- 不重复 `workflow.md` STEP 10 的九项 Test；本文件只定义它们的**调用时机**。
